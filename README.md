# 桌宠（Windows 桌面宠物）

一个常驻系统托盘的桌面宠物：养一张透明 PNG「小人」——摸头、喂食、1:1 拖动、抛掷物理、
吸附到其它窗口顶沿挂着、长按锁定、休息（透明闪烁回体力）、状态养成、背景图、BGM、待办到期提醒 +
♥ 待办随机催促、自定义关键词聊天、眨眼动画（呼吸零点触发 + 多帧序列）、随机特效动画（动画1/动画2）、
切换状态（换一具身体）。
**「学习」菜单**：学英语（翻译练习 / 选词填空 / 背单词间隔重复 + 四选一/拼写题型 + 小测 + 统计打卡 +
积分段位 + 桌宠催背，初中到专八 7 档词库，6 套主题、柔和/标准配色）+ **番茄钟**（预设/自定义时长）+
**学习计划表**（周视图日程窗，桌宠主图缩小后作装饰）。
**语音聊天**（可选）：离线语音识别（sherpa-onnx）+ 后台唤醒词 + **语音对话**（聊天窗 🎤 进入，自动连续多轮）+
**按键说话**（全局键按一下进入/退出、聊天窗内按住说话，键位都可自定义）。
**聊天记录**：独立 json 存在**便携目录之外**（默认 `~/.deskpet/chat.json`），关窗重开还在、可翻阅。
**像素级点击穿透 + 像素级碰撞**：宠物透明处鼠标能点到桌面/其它程序，只有实心像素可交互；
物理落地/贴墙/吸附也以不透明像素为准（透明边距不参与碰撞）。
纯 Electron；唯一原生依赖是 **`sherpa-onnx-node`**（语音识别用，Node-API 免 `electron-rebuild`，
不装也不影响其它功能）；「枚举其它窗口/写窗口样式」仍走系统 .NET 的 csc.exe 现编译的 C# 小程序。

## 运行

前置：Node ≥ 18、npm。首次 `npm install`（国内慢可设
`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`）——会一并装上 `sherpa-onnx-node`
与它的 Windows 原生二进制（optional 依赖 `sherpa-onnx-win-x64`，约 22MB，免编译器）。

- 双击 `启动桌宠.bat` —— **免装 Node**，分发/给别的电脑用这个；`启动桌宠-调试.bat` 带控制台日志（PET_DEBUG=1）。
- 开发：`npm start`。
- 退出：右键长按宠物 → 主菜单「退出」，或托盘图标右键 → 退出。

**语音（可选，不用就完全无感）**：需要模型文件，按需下载：

```bash
npm run voice:fetch        # 识别模型 + 唤醒词模型 → data/voice/models/（断点续传，重跑接着下）
npm run voice:fetch -- --model small-ctc-zh-int8   # 慢网先下轻量档（解压后约 25MB）
npm run voice:fetch -- --from "D:\下载\sherpa-onnx-....tar.bz2"   # 或用本地下好的压缩包
npm run voice:spike        # 自检（★ 不需要麦克风）：插件/关键类/模型齐全/唤醒词 token/**端到端识别出中文**
npm run voice:spike:electron   # 同上，但用 Electron 运行时（验证 Node-API ABI 兼容）
npm run voice:diag         # 全链路诊断（开麦约 3 秒）：麦克风 / 隐藏窗 AudioContext / 音频帧电平 / asr:init
```

**缺模型不会崩也不会卡**：语音整体优雅隐藏（聊天窗不显示麦克风按钮，设置窗提示"模型未安装"），
其余功能一切照常。详细说明见下面「语音聊天」一节。

**便携化**：全部数据（设置 `settings.json`、上传素材副本、Chromium 缓存、**语音模型**）都在**应用文件夹内 `data/`**，
不写 `%APPDATA%`、不写注册表。把整个文件夹（**含 `node_modules`**）拷到别的 Windows 电脑双击
`启动桌宠.bat` 即用；settings 里的文件路径都是相对 `data/` 的，改名/换盘符不断链。
旧版 `%APPDATA%\桌宠\` 的数据会在新版首次启动时一次性拷进来（迁移是拷贝不是移动）。
**唯二的例外 = 大模型 API 密钥 + 聊天记录**：它们**刻意放在便携目录之外**（默认都在 `~/.deskpet/` 下），
这样"把文件夹拷给别人 / 发出去"不会把密钥和聊天内容一起送出去；换电脑后第一次用到时会自动创建。
已知边界：文件夹需放在**可写位置**（`data/` 要能创建）；Windows x64；按**单主屏**设计。

## 特色功能（快速说明）

- **状态系统**：情绪/体力/饱食/好感（0–100，每秒结算）。**桌宠不在你面前时（应用关闭 / 窗口隐藏）
  这段时间默认"冻结"**——只有它在眼前时时间才算数，免得关掉电脑过一夜、第二天回来看到一只被算到 0 的
  宠物（`config.status.decayWhileAway` 可改回旧的"离线也流逝"行为）。
  状态胶囊左上角显示 `☺ ⚡ 🍖`，好感 >0 加 `♥`；点击折叠。主动互动=摸头/锁定切换/拖动结束/喂食/聊天未命中。
  好感每次互动 2% +1，每满 20 点触发 ♥ 爱心上浮。
- **待办**：独立窗口，添加（≤200 字 + 截止到分钟 + ♥）、完成划线、删除；持久化。后台每 30s 检查，
  到期未完成 → 气泡「主人，该做"xxx"了！」（5s，每条本运行内只提醒一次；锁定态照弹但穿透点不了）。
- **随机催促**：每 25~30 分钟随机一次（概率性），从 ♥ 未完成待办**按紧迫度加权**挑一条
  （≤10 分钟/过期 ×10、≤1h ×2）→ 气泡「主人，'xxx' 做完了吗？」8s。锁定或隐藏不催。无去重。
- **聊天**：聊天窗（历史仅窗口期内）+ 设置窗（规则持久化 + **回复引擎**选择）。规则忽略大小写「包含」匹配、多命中取最长关键词；
  命中 → 聊天窗回复 + 主窗气泡 5s；**未命中 → 主窗 Q 弹 + 情绪 +2**。回复引擎可扩展（rule 现用 / llm 预留），
  引擎不可用会自动回落 rule —— 详见「聊天引擎」。
- **语音聊天**（可选）：离线识别 + 后台唤醒词 + 聊天窗 🎤 进入的**语音对话**（自动连续多轮，无需重复唤醒）
  + **按键说话**（全局键 = 按一下进入/再按退出；聊天窗内 = 按住说话、松开立即提交；键位可自定义）；
  音频不出本机、不落盘、不联网。详见「语音聊天」。
- **背景图**：应用内选 PNG，图**底边贴区域地面**、高=人物高 ×4/3 宽等比；人物站在地面时背景水平居中跟随脚底，
  抛起/拎高时背景停住，落地重对齐。「清除背景」即时复原。不透明度四档。
- **BGM**：应用内选曲（mp3/wav/ogg/flac/m4a/aac）拷贝进 assets 自动开播（若未在播），面板可连续加；
  放完自动下一首、损坏文件 800ms 限频跳歌。启动加载列表但不自动播；隐藏暂停、恢复不续播。**无音量 UI**（默认
  `config.js audio.volumeDefault`=0.6）。
- **眨眼**（2026-09-10~09-27 曾把自动触发注释关闭，现已恢复）：主循环逐帧检测**呼吸缩放偏移归零（符号翻转）**
  的零点，每个零点按 `config.js blink.zeroChance`（默认 90%）掷骰触发；**未配置多帧**则降级为单图 `src/assets/blink.png`
  （替换同名文件生效；内置占位图与主图同画布同脚底、只差眼睛开合，见「换图即定制（素材）」）显示 150ms；**配置了多帧**（`blinkAnim.frames`）则按序播帧
  （每帧各自 durationMs）。叠加层**跟随实时呼吸缩放**（图层切换尺度完全连续，不抖动）。
  眨眼只属主形象：状态图形态不眨眼。呼吸幅度为 0（`anim.breatheAmplitude`）或暂停/拖动/飞行时没有零点 → 自然不眨。
  **休息（睡觉）期间眨眼与特效都不起播**（`canStartOverlay` 排除 rest）：叠加帧是整幅不透明的"换一具身体"，
  会把 25%↔75% 的睡颜闪烁顶掉一瞬。自动触发这条链路由 UI 场景 `blink` 兜底——它会真的等到一次"没人调用"的眨眼
  （这段曾被关闭 17 天而没有任何测试变红，就是因为只测了播放机制）。
- **随机特效动画**：素材 = `动画素材/动画1、动画2`（各三帧，`config.js effectAnim.groups` 可改；内置为火柴人
  单手挥手 / 原地起跳各三帧，与主图同画布同脚底）。
  每次播完/跳过后在 **15~25s** 随机取间隔再试；到点挂起，等下一个**呼吸零点**起播（本体恰在未变形尺寸，
  图层切换无跳变）；播放时**整帧替换**本体（隐藏本体防双影）、跟随呼吸缩放、暂停透明度变化，播完恢复。
  **与眨眼互斥**（特效优先）；拖动/物理/手势/切形态/隐藏时跳过本轮。
- **切换状态（换一具身体）**：菜单「切换状态」两个单选项直达目标形态。语义是**换一具完整身体**不是贴图：
  状态图走同一解码管线（等比缩放≤220px → 位图分析 → 实体中心锚点），切换后**像素判定/拖动/抛掷/吸附/
  呼吸/背景跟随等全部功能照常作用于新身体**；切换保持「底边中点」原地连续。状态数值不变；形态**不持久化**
  （重启回主宠物图）。状态图默认 `src/assets/state.png`（替换同名文件生效），也可 `config.js stateImage.path`
  指定本地图覆盖路径（尺寸可与主图不同）。

## 学英语（独立学习窗口）

入口：主菜单 → **学习 ▸ 学英语**（2026-09-14 起从「聊天」子菜单迁到这里）。四个 Tab：翻译练习 / 选词填空 / 背单词 / 学习统计；右上角 ⚙ 设置。

- **翻译练习**：词书例句中英互译；本地判分（精确匹配 + 关键词/bigram 重叠率），正确/接近/错误三档并给参考答案；无任何外部 API。
- **选词填空**：约 70% 优先词书自带真题（含中文解析），其余程序生成（挖目标词，**永不挖主语**）；干扰项 = 固定介词/连词池或同书随机词；键盘 1-4 作答。
- **背单词**：新词走"翻卡 → 四选一 → 拼写"三连自动结卡；复习先自测再打认识/不认识；Leitner 间隔重复（10min→1h→1d→3d→7d→14d→30d，答错降 2 档 10 分钟后重现）；每学 10 张卡插一轮 6 题混合小测；系统离线 TTS 发音（无英文音色自动隐藏按钮）；☆ 生词本 +「只背生词本」模式；📖 词表浏览（搜索/详情/徽标）。
- **难度**：初中/高中/四级/六级/考研/雅思/专八 7 档，词库在 `data\english\words.<难度>.json`（缺文件 = "该难度暂无数据"）。
- **积分段位**：近 90 天加权积分（30 天内 ×1 / 30–60 天 ×0.5 / 60–90 天 ×0.25，每天封顶 80 分）——**长期不背自然掉分**；段位 未评级→A1→A2→B1→B2→C1→C2；积分摘要预留联网排行榜上报接口（当前完全离线，不上传任何数据）。
- **桌宠催背**：设置里选频率（关闭 / 15 分钟 / 30 分钟 / 1 / 2 / 4 / 8 小时），到点桌宠气泡报当天剩余词量；只在 8:00–23:00 弹。
- **设置（⚙）**：6 套主题、配色浓度 柔和(默认)/标准、每日新词 5~100、复习:新词比例（复习优先/3:1/2:1/1:1/1:2）、题型开关、催背频率；全部持久化在 `settings.json` 的 `english` 字段。学习进度在 `data\english\progress.json`。

## 番茄钟（学习 ▸ 番茄钟）

独立窗口，专注 / 短休 / 长休自动轮转：专注 → 短休 → 专注 → …，**每完成 N 个专注插一次长休**（N 可改，默认 4）。

- **预设 + 自定义**：专注 15/25/45/60、短休 5/10、长休 15/30 做成快捷按钮；也能直接填任意 **1~180 分钟**。
  改动即时生效（下一次重置/切段按新时长走）并记住到下次启动（`settings.json` 的 `pomodoro`）。
- 按钮：开始/暂停/继续、重置（回到第一段专注、计数清零）、跳过（切下一段，**不计入已完成数**）。
- **完成一个专注 → 桌宠给反馈**：好感度 +2、情绪 +2（2026-09-17 起奖励改为加好感，跨里程碑会飘爱心），并弹一句夸奖气泡（走 `bubble:chat` 通道，与其它气泡一致）。
- **学习记录与成就（2026-09-17 起）**：窗口内有「计时 / 记录 / 成就」三个标签页。
  - 计时页可填"这次学什么"标签（选填，记入该次记录）；

## 语音聊天（可选：离线识别 + 后台唤醒 + 语音对话 + 按键说话）

> 入口：**聊天 ▸ 语音聊天设置…**；说话入口：**聊天窗 🎤**、**按键说话**、**唤醒词**（三种可同时用）。
> **全部离线**：音频不出本机、默认不保存录音、不联网（与"学英语完全离线"同一承诺）。

### 交互模型（2026-09-16 改版：4 种"触发方式"取消，但按键说话当晚又恢复了）

聊天窗**常态是打字**；想用语音，四条路任选：

| 入口 | 行为 |
| --- | --- |
| **语音对话**（聊天窗 🎤，点一下进入 / 再点退出） | 进入后**自动连续多轮**：说完静音约 1.2 秒自动断句 → **停掉麦克风**等模型回复 → 回复到了自动接着听，**不需要任何点击** |
| **全局按键**（设置窗自定义，**默认不设**） | **任何窗口**都能按：按一下 = 进入语音对话（等价于点 🎤），再按一下 = 退出 |
| **聊天窗内按键**（默认 `Ctrl + Shift + Space`） | **按住说话**；**松开立即提交这一句**（不必等那 1.2 秒静音），提交后照常接着听 |
| **后台唤醒**（设置窗开关，默认开） | 没开聊天窗时也能喊一声叫醒我，代价是**麦克风常驻监听**；关掉它就只剩上面三种"主动"入口 |

一轮语音对话的细节（都是用户明确要求的）：

- **过短不请求大模型**：「啊」一声、或去掉标点后不足 2 个字 → 不算一句话，只在状态条上轻提示
  （阈值 `config.voice.dialog.{minSpeechMs,minChars}`：有效人声 ≥350ms **且** ≥2 字）。
- **等模型期间不做识别**：提交后立刻停掉采集（Windows 的麦克风占用提示会熄灭），
  避免把环境音当成下一句；回复到了（成功/失败/回落都算）自动恢复，带 30 秒兜底定时器防"永久哑掉"。
- **不切回打字**：一轮结束仍留在语音对话里，直到你再点一次 🎤。
- **关掉聊天窗 = 退出语音对话**；后台唤醒（若开着）不受影响。

### 按键说话（键位可自定义）

在设置窗里**点一下键位框 → 直接按下你想用的键**就记下来了（Esc 取消）。两个键位**故意分开**：

| 形态 | 交互 | 默认 | 说明 |
| --- | --- | --- | --- |
| 聊天窗内 | **按住说话**（松开立即提交） | `Ctrl + Shift + Space` | 有 keydown + keyup，是真正的"按住" |
| 全局 | **按一下进入 / 再按一下退出** | 空（不注册） | 任何窗口都能按，但**该键会被桌宠独占** |

两条必须知道的原因：

- **为什么全局不是"按住"**：Electron 的 `globalShortcut` **只给 keydown、没有 keyup**，
  所以系统层面只可能做成"按一下切换"。这不是偷懒，是 API 限制（`config.voice.ptt` 与
  `shared/voice.js` 的注释里都写了）。
- **为什么默认不是 `Ctrl + 空格`**：那是 **Windows 中文输入法的中英切换**，按键会先被输入法吃掉，
  桌宠根本收不到（2026-09-15 踩过）。全局键默认**留空不注册** —— 不替用户平白占按键。
- 录到**单键**（例如就用 `F2`）会明确警告"会全局独占、影响打字"；某个键**已被其它程序占用**时，
  保存会如实提示"这个键已被其它程序占用"，不会让你"设了却没反应"。

> **沿革（为什么这段读起来像在辩解）**：按键说话在 2026-09-16 白天**曾被取消**（当时判断它与语音对话
> 互斥），**当晚按用户要求恢复**。现在两者**共存**：语音对话是"会话状态"，按键只是进入/退出与
> "提前提交"的快捷方式。
> 恢复时特别守住了 §38 那个坑：判断"按一下是开始还是结束"**只能用 `voice.isDialogOn()`**，
> **绝不能**用 `state !== 'idle'` —— 开着唤醒监听时状态是 `listening`，会被误判成"要停止"，
> 于是全局键在唤醒模式下按了毫无反应。

### 唤醒词（用户自定）

唤醒词**不是写死**的，在设置窗里改。实现上有一个必须知道的事实：
**识别引擎吃的是"音素串"而不是汉字**（sherpa-onnx 的 `keywords.txt` 格式：`x iǎo ài t óng x ué :1.5 #0.25 @小爱同学`）。
本项目不依赖 Python，所以把「中文 → 音素串」预先做进 `config.voice.wake.builtin` 内置词库（5 个常用唤醒词），
设置窗里可以直接挑；想要别的词就手填音素串（高级项），并可调 **灵敏度**（`:boost` 越大越易触发、`#threshold` 越大越严）。
设置窗会**实时显示生成的关键词串**，空串会明确提示"唤醒不会触发"。

### 模型

放 `data/voice/models/<档位目录>/`，随 `data/` 便携、不进 git。档位是白名单（手改 settings 指向别的 id 会被拒）：

| 档位 id | 说明 |
| --- | --- |
| `zipformer-zh-int8`（默认） | 中文 · 均衡，**压缩包 153MB**，流式（边说边出字） |
| `small-ctc-zh-int8` | 中文 · 轻量，**压缩包 20MB / 解压后 25MB**，流式（**慢网/老旧机器首选**） |
| `sense-voice-int8` | 中英日韩粤 · 高精度，非流式（说完再出字） |

> 体积为 2026-09-14 实测（GitHub release 的 content-length + 解压后核对）。
> 唤醒词另需 **KWS 模型：压缩包 31MB**（官方标的 "3.3M" 是**参数量**，不是下载体积 —— 别被它误导）。
>
> **⚠️ 两组模型分处两个 GitHub release**：识别模型在 `asr-models`，**唤醒词在 `kws-models`**
> —— 早期版本一律用 `asr-models`，取 KWS 那个文件恒返回 502，于是**唤醒功能永远装不上**。脚本已修正。
>
> **⚠️ 三种模型结构不能混为一谈**（`config.voice.models[].kind` 标明，推理时按它填不同参数）：
> `transducer`（encoder+decoder+joiner 三件套）/ `zipformer2Ctc`（**单文件** + `bbpe.model` 做 BPE 词表）/
> `senseVoice`（单文件、非流式）。把 CTC 档当成三件套去查文件，会误报"缺 encoder/decoder/joiner"。

```bash
npm run voice:fetch                                 # 识别模型（config 选定档位）+ 唤醒词模型
npm run voice:fetch -- --model small-ctc-zh-int8     # ★ 慢网就下这个：只有 20MB，先把链路跑通
npm run voice:fetch -- --kws                         # 只补唤醒词模型（3.3MB）
npm run voice:fetch -- --all                         # 三个档位全下（体积大）
npm run voice:fetch -- --from "D:\下载\sherpa-onnx-....tar.bz2"
                                                     # 用本地下好的压缩包（浏览器/下载工具拉完再喂进来）
```

**下载是断点续传的**：走系统自带 curl（`-C -` 续传 + 失败自动重试 + 只在"卡住"时才放弃），
中断/超时后**重跑同一条命令即接着下**。早先手写的下载器有真问题：固定 2 分钟超时、
且号称续传实则没实现 —— 慢网下等于永远下不完。

**排查顺序（先排除最蠢也最贵的那个原因：组件压根没被启动）**：

[voice-e2e] {"available":false,...,"loading":true,"stage":"recognizer-ok",...}
[voice-e2e] {"available":true,...,"modelReady":true,"stage":"ready-sent"}

`voice:diag` 把"为什么不出字/唤不醒"拆成 7 步逐项打勾，直接指出该修哪里：

| 步骤 | 查什么 |
| --- | --- |

| ② | 识别模型文件是否齐全（encoder/decoder/joiner/tokens） |

### 降级矩阵（都必须成立，这是"不会崩"的保证）

| 场景 | 表现 |
| --- | --- |
| 模型未下载 | `voice:status.available=false / reason:'no-model'`；聊天窗**不显示** 🎤 按钮；设置窗提示"语音模型未安装"；**按快捷键会弹气泡说明原因**（不会静默无反应）；其余功能照常 |
| 模型**正在加载**（首次 1~3 秒） | `status.loading=true` → 文案是"正在加载模型，稍等一下"（**不是**笼统的"没准备好"），避免用户误判成坏了 |
| 无麦克风 / 权限被拒 | 气泡提示"没找到麦克风"；识别进程不启动 |
| 原生插件加载失败 | 捕获异常 → 禁用语音并写日志（**不会**影响启动） |
| 没听清（空/纯标点） | 提示"没听清，再说一次？"，**不调用聊天引擎**（避免空话触发表情） |
| 识别进程**卡住**（不崩也不 ready） | `config.voice.readyTimeoutMs`（默认 20s）到点 → 销毁旧进程并**受控重建**；最多 `readyMaxRetries`（默认 3）次，超限则明确报错（`reason:'crashed'` + 原因），不再无意义重试 |
| 识别页面加载失败（`did-fail-load`） | 记下原因**并重建**（早期只记日志不重试 → 一次偶发失败 = 本次开机语音全废） |
| 识别进程崩溃 | 10 分钟内最多自动重启 3 次，超限则禁用并提示 |
| 启动接线万一失效 | 所有语音 IPC 入口先过 `ensureVoiceService()` **惰性补启** → 用户第一次点击就能救回来（不必重启应用） |
| 用户主动"重试" | 「语音聊天设置 → 重试（重建语音引擎）」：重建进程并**重置重试配额与崩溃冷却**（否则被停用后再也起不来） |
| 说话期间拖拽宠物 / 弹菜单 | 互不干扰（音频在独立进程，手势在主进程/宠物窗） |

### 实现要点（改这块前必读）

- **启动接线（★ 血的教训）**：语音服务必须在 `PetApp.init()` 里被**显式启动**（`this.startVoice()`）。
  2026-09-15 的事故是：`startVoice()` 全部写好、却**没有任何调用点** → `this.voice` 恒为 `null`
  → 聊天窗 🎤 永不出现、按快捷键只回一句"引擎没准备好"。
  这类 bug 纯函数单测测不出（不碰启动流程）、`voice:diag` 也测不出（它自己 `new VoiceService()`、绕过接线），
  所以补了两道网：`test/unit/voice-wiring.test.js`（把主进程 boot 一遍再断言接线）与 `npm run voice:e2e`
  （走真实启动路径等 `asr:ready`）。**改启动流程后请务必跑这两个。**
  另外三层自愈保证它不会再变成死局：①所有语音 IPC 入口 `ensureVoiceService()` 惰性补启
  ②卡住/加载失败 → 受控重建（有上限）③崩溃 → 有限次重启。**加新的语音入口时也请先过 `ensureVoiceService()`。**
- **推理绝不在主进程**：主进程每 16ms 推光标驱动像素穿透判定（"点得动"的命脉），一次同步 ONNX 推理就能
  把它抖成"点不动"。所以采集（AudioWorklet，失败自动退回 ScriptProcessor）与推理**同处一个隐藏渲染进程**
  （`renderer/asr.html` + `asr.js`）→ **PCM 一次都不跨进程**，主进程只收文本。
- **文字与语音同源**：`chatSend(text)` 与 `voiceFinal(text)` 都交给 `ChatOrchestrator.handle(ChatRequest)`，
  **唯一差别是 `req.channel`**（`'text'` / `'voice'`）。识别结果复用现有 `bubble:chat` 气泡通道；
  语音来源的回复额外推一条到聊天窗（`chat:message`），文字来源仍由聊天窗自己渲染 → 不重不漏。
- **权限放行**：主进程 `session.setPermissionRequestHandler` 放行 `media`（不放行 `getUserMedia` 会被直接 reject）。
- **BGM 闪避**：听/识别期间自动把 BGM 压到 `config.audio.duckVolume`（默认 0.15），否则麦克风会把自己的音乐收进去。
  可在设置窗关掉。
- **视觉反馈（★ 呈现规则）**：分两种场合，别混：
  - **后台等唤醒词**（没进语音对话，`state='listening'`）→ **桌面完全安静**，不显示任何「在听/待唤醒」
    小窗（用户 2026-09-15 定调：后台监听不该扰动界面）；
  - **进入了语音对话**（用户主动点 🎤）→ 宠物头顶显示「在听…/听到：…」+ 电平条，说完自动收起。
  指示是 `pointer-events:none` 且**故意不进 `updateUiRects()`** —— 纯装饰，不给像素穿透判定添新矩形（红线）。
- **气泡要给语音提示条让位**（2026-09-16 修）：两者原本都锚在宠物头顶同一处，一行气泡会盖住提示条
  24px 里的 18px，看着"互相冲突、反复闪动"。现在 `layoutBubble()` 会把提示条占的高度算进偏移
  （提示条在时气泡上移、收起后落回），位置变化同步 `updateUiRects()`。
- **聊天窗"正在输入"显示**：没进语音对话时保持安静；进入后显示「语音对话中…」/「在想…」（等模型期间）/
  「正在识别：xxx」+ 实时字幕 + 电平条；过短被丢弃时给一句轻提示。
  识别完成后，**识别出的"我说的那句"会作为一条消息进入对话**（`who='me'`）。
- **语音对话的状态机**（改这块前必读）：识别侧 `session = null | 'dialog' | 'oneshot'`
  （`asr:start{session:'dialog'}` 进入、`asr:stop` 退出、`asr:resume` 接着听）；
  主进程 `VoiceService` 持有 `dialog / thinking` 并对外广播 `voice:dialog`。
  **说完一句必须走 `afterUtterance()`**（成功 / 失败 / 回落 / 过短都要）—— 它是"恢复听"的唯一出口，
  漏掉任何一条分支就会出现"某次失败后语音再也不理你"。
- **采集节点（AudioWorklet）必须接进"通向 destination"的音频图**：Chromium 只驱动能到达输出端的节点。
  早期版本为了"避免听到自己"把 worklet 悬空不连下游 → 它的 `process()` **从不被调用、一帧音频都收不到，
  而且不报任何错**，表现就是"麦克风开着但什么都识别不出来"。现在用 **0 增益 sink** 兜到 destination
  （图是通的、完全静音、不外放）。另挂**看门狗**：起采 1.5 秒仍 0 帧就自动回退 `ScriptProcessorNode`
  —— 不假设哪条路径一定行，以"是否真收到帧"为准。
- **排查语音问题先看 `data/debug.log`**：`PET_DEBUG=1` 会把日志落盘（Windows 下双击 .bat 没有控制台，
  用 `Start-Process` 重定向也抓不到 Electron 主进程输出）。识别进程的 console 会转发进同一份日志，
  并带**阶段上报**：`init-received → require-ok → recognizer-ok → kws-ok → devices-ok → ready-sent`，
  卡在哪一步一目了然 —— 这比"语音引擎还没准备好"这种笼统提示有用得多。
- **`sherpa-onnx` 的 `readWave` 在 Electron 里会抛 `External buffers are not allowed`**（它返回 C++ 侧
  外部缓冲，Electron 不允许；纯 Node 下正常）→ 自检脚本改用 `shared/voice.js` 的 `parseWavPcm16()`
  自己解析（纯函数、有单测）。
- **两条接缝，别绕过去**：①音频只在识别进程内流动 ②文本只从 `voiceFinal` 进聊天系统。

- **谁写**：**主进程是唯一写入方**。以前"文字路径渲染层自己画 + 语音路径主进程推"两条路并存，

  即使它已经丢弃了旧内容，界面上照样能往上翻。

## 聊天引擎（ChatEngine 契约 + 大模型）

规则是**引擎无关**的：文字与语音最终都变成一条 `ChatRequest`，引擎不知道这句话从哪来。

- **契约**：`src/shared/chat/engine.js` 定义 `ChatRequest / ChatResult / ChatEngine`（JSDoc typedef）；
  注册表提供 `registerEngine / listEngines / selectEngine`。内置两个引擎：
  - `rule`（默认）＝「关键词 → 回复」，离线、零网络行为；
  - `llm` ＝**OpenAI 兼容大模型**（DeepSeek / OpenAI / Moonshot / 通义 / 智谱 / 本地 Ollama 都能接）。
- **降级是自动的（两道）**：① `selectEngine` 发现目标引擎不可用（没配密钥/地址）→ 回落 `rule` 并回报
  `degradedFrom`；② **请求失败也会回落**（401/404/429/超时/离线/响应解析失败）→ 桌宠照常有反应，
  聊天窗里写明失败原因。切换入口：**聊天设置 → 回复引擎**。
- **配置**：聊天设置窗 → 展开「大模型设置」，填 服务商预设 / base_url / 模型名 / 密钥 / 人设 / 温度 /
  最大字数 / 超时 / 历史轮数 / 重试次数；「测试连接」会把结果分清楚
  （成功 / 401 密钥错 / 404 地址错 / 模型不存在 / 网络不可达 / 超时 / base_url 非法），不是笼统一句"失败"。
  参数默认值都在 `config.js chatEngine.engines.llm`（唯一调参入口）。
- **★ 密钥放哪（三条红线）**：① **不写进 `settings.json`**（该文件随便携 `data/` 拷来拷去）——密钥存在
  **一个独立的明文文件**里，默认 **`~/.deskpet/llm.key`**（即 `C:\Users\<你>\.deskpet\llm.key`）；
  ② 出网请求只在**主进程**，渲染层永不接触密钥（设置窗输入框存完即清空）；
  ③ 密钥不进日志/错误信息（引擎里还有一道 `sk-***` 脱敏兜底）。
  - **为什么放在主目录而不是 `data/`**：`data/` 是便携设计，**把桌宠文件夹拷给别人就等于把密钥一起送出去**。
    放在便携目录之外 = 拷走文件夹不带密钥；**换电脑后第一次保存密钥时目录自动创建**（不用手工建路径）。
    这条不变量有断言守着：单测 `isInsideDir` + 自检 `密钥文件仍在便携目录之外` + 递归扫描便携目录确认无明文。
  - **明文**是刻意的（用户决策）：可以直接用记事本打开改，也能手工写 `KEY=sk-xxx` 形式。
    能读到你这个 Windows 用户目录的人就能看到它 —— 请自行保护账户。
  - 路径改法：`config.js → chatEngine.engines.llm.keyFile`（支持 `~`；相对路径按主目录解析）。
    ⚠ 别改到 `data/` 里面，那等于把红线拆了（设置窗会显示实际路径并在落到程序目录内时报警）。
  - 设置窗有「**打开密钥文件位置**」按钮，直接在资源管理器里定位到它。
  - 另支持环境变量后备：`chatEngine.engines.llm.apiKeyEnv` 存的是**环境变量名**（密钥文件里没有密钥时才读它）。
- **超时 / 取消 / 重试**：超时可配（默认 10s，可调到 3s 做测试）；请求中途可**取消**（聊天窗「停止」按钮或 Esc，
  也可用新的一句顶掉上一句）；**只有 429 / 5xx / 网络抖动**才按指数退避重试 `retryMax` 次（默认 2，
  **绝不无限重试**），超时与取消不重试。
- **人设与字数（决定"它聊起来像不像人"）**：`systemPrompt`（人设）+ 自动拼的上下文摘要 + 硬约束
  `replyRules`（"不超过 {maxChars} 字…"）→ 三者拼成 system 发给模型。默认值见 `config.js`
  第 359 / 361 / **372**（`systemPrompt`）/ **374**（`replyRules`）行
  —— ⚠ 行号会随注释增删漂移，**更稳的定位是直接搜 `systemPrompt:` 和 `replyRules:`**。
  ⚠ 这两项的**可改性不同**：人设在设置窗里能改（`settings.chatEngine.llm.systemPrompt`，**留空则回落 config**）；
  而 **`replyRules` 在设置窗里改不了**（表单根本不提交这个字段，`readLlmForm()` 只收 systemPrompt/温度/字数等），
  **要改只能改 `config.js` 并重启应用**。
  ⚠ **`replyRules` 里那句「不要复述用户的问题」会明显把对话压平**（它砍掉了"先接住你说的具体内容"这条最自然的
  回应路径，模型只剩泛泛而谈）；觉得桌宠太呆时**优先改这一句**，而不是去调模型。
  ⚠ 上下文摘要目前**只有待办条数与英语难度**，`ctx.status`（心情/体力）是**未接线的死分支**（`buildContext()` 不填）。
  回复超长按 `maxChars` 截断（默认 300；**气泡只有 260px 宽、5s** —— 300 字约占 17 行/348px，且气泡参与
  `updateUiRects()` 命中判定，会挡住底下窗口的点击；想要短一点就把它调回 120 左右）。
  历史按 `historyTurns` + 字数预算截窗，**只存内存**（重启即清；聊天记录虽已落盘，但**不喂回模型**）。
- **流式（打字机）**：`stream: true` 时走 SSE（解析器在 `src/shared/chat/sse.js`，纯函数有单测），
  增量按 `streamDeltaMs` 节流后推给宠物窗气泡（复用既有 `bubble:chat` 通道，**渲染层零改动**）。
  流式与非流式是两条代码路径，**超时/取消/重试/截断/回落/日志在两条路径上能力对齐**（有单测与自检覆盖）。
- **请求日志面板**：聊天设置窗底部显示最近 50 条（时间 / 耗时 / HTTP 状态码 / tokens / 走了哪条路径
  `大模型·流式`/`大模型`/`回落`/`重试中`）——排查"到底是没发出去、被限流还是回落了"不用靠猜。
- **调试开关**：设置里勾「调试：强制回落」即可测兜底链路，不必拔网线。
- 想加第三个引擎 = 在 `src/shared/chat/` 新建文件 + `index.js` 里 require 一行；契约、编排器、UI 都不用动。

## 关键机制与边界（改代码前先读）

- **像素穿透（红线）**：整个"活动区域"是**一个**无边框透明置顶窗口；主进程每 ~16ms 推真实光标，
  渲染层每帧用**当前身体的原始位图**（alpha≥20）+ 打开的 UI 矩形命中 → 命中窗口接鼠标、未命中
  `setIgnoreMouseEvents(true,{forward:true})` 穿透。**判定只动原始像素，动画只走 CSS transform / 叠加层**，
  互不影响。锁定时无论在哪都整窗穿透。光标 IPC 到达时**直接驱动一次命中判定**（与 rAF 解耦兜底，
  页面被节流/遮挡停转也能恢复穿透）。
- **像素级碰撞（红线 2）**：解码时从不透明像素包围盒折算出**碰撞盒**（`col`，相对 pos 的偏移/尺寸），
  物理边界钳制/落地/贴墙/吸附贴顶/背景贴地跟随全部以不透明范围为准，**透明区域不参与碰撞**
  （落地不再"悬空"，贴墙不再被透明边距顶住）；点击判定与碰撞盒用同一份不透明数据。
- **不冻结其它窗口 / 不抢前台（三层防护，勿删）**：① 宠物窗带 **`WS_EX_TOOLWINDOW`**（启动时经
  `winstyle.exe` 写入扩展样式，Chromium 系应用的遮挡检测**永久跳过**本窗——根治）② `focusable:false`
  （点击不抢前台）③ 恢复穿透瞬间的重置置顶级（z-order 兜底，对 Chrome/Edge 无效但保留）。另：
  启动即 **`disable-features=CalculateNativeWinOcclusion`**（自己被判"被遮挡"→ rAF 停转 → 点不动的根治）；
  所有窗口 **`spellcheck:false`**（否则 Chromium 拼写检查会在进程 cwd 造乱码垃圾目录）、autoplay 放开开关已加。
- **置顶级别恒为最高档（screen-saver）**：锁定/解锁差异只在"是否整窗穿透"，不在层级（低级别会被其它
  置顶/全屏应用遮挡）；"伸手即置顶"——从穿透转可交互的瞬间主进程 `moveTop()` 抬到 z 序最上。
- **点击判定细节**：气泡/胶囊/面板/选择器等 UI 矩形参与命中；气泡显示时指针在气泡上窗口可交互、可点关。
- **呼吸零点仲裁**：眨眼与特效动画都以"主呼吸波偏移归零（符号翻转）"为起播门禁、以**状态标志**互斥
  （特效优先）；等待期间条件变化（互动/切形态/隐藏）即放弃。呼吸在拖动/飞行中**相位冻结**，恢复时
  幅度 0.5s 内从 0 渐回满幅（衔接连续不突跳）。
- **窗口**：宠物窗 + 待办/聊天/聊天设置/学英语/番茄钟/学习计划表/语音聊天设置 7 个工具窗 +
  **语音识别进程**（`asr.html`，隐藏窗、无 UI，跑采集与推理）；托盘常驻（关窗不退出），单实例锁。
  工具窗统一由 `openToolWindow()` 创建（同一套 webPreferences：`spellcheck:false`、`backgroundThrottling:false`）。
- **吸附**：锚点=实体像素包围盒中心；锚点水平落在窗口范围±25px、距其顶沿≤120px、释放为低速 → 挂住
  （碰撞盒底边贴顶）；目标被移动/最小化/关闭 → 坠落。每 400ms 轮询；枚举走异步 spawn（不阻塞主进程）。
- **弹菜单手势清理**：Windows 弹原生菜单会吞松键 → 渲染层弹菜单前 + `menu:closed` 后各清一次手势态
  （否则"选完菜单项人物被吸到鼠标"）。
- **发射契约**：事件总线 `emit` 是**单参 kind**（`emit('feed')`，不是 `emit(kind,data)`）——改它会让喂食回归。
- 已知怪癖：宠物位置 `pos` 只写不读（重启总回底部居中）；播放列表 `name` 字段重载后丢（无 UI 显示，无感）；
  到期提醒锁定照弹 vs 随机催促锁定不触发（差异是有意为之）；单主屏设计；聊天历史不持久化。

## 定制与调参（改 config.js）

**所有**可调参数、文案、菜单、素材路径集中在一个文件：`src/shared/config.js`（模块加载即深冻结；
每键有中文注释）。**config.js 就是唯一调参/定制入口**（不再有开发者模式/固化文件/覆盖层——已整体精简掉）。
常见定制：改启动问候 `greeting.greetings`、到期/催促文案 `todo.remindTemplate`/`reminder.template`、
聊天文案 `chat.strings`、菜单文本与隐藏 `menu.items`、眨眼（零点触发概率 `blink.zeroChance`、多帧
`blinkAnim`）、随机特效动画 `effectAnim`（组/帧/间隔；帧 path 以 `../` 开头 = 相对 `src/renderer/` 的内置
素材，其余相对 `data/` 或绝对路径）、状态图路径 `stateImage.path`、全部手感/物理/状态/背景参数。
新增的几块也可直接改：**`chatEngine`**（引擎与 LLM 预留参数；`logFile`/`logMax` 是**聊天记录**的存放位置与条数上限）、
**`voice`**（「后台唤醒」开关 `wake.enabled` + **按键说话键位 `ptt.{local,globalKey}`** + 唤醒词内置词库 `wake.builtin` + 模型白名单 `models` +
端点静音 `endpointSilenceMs` + 语音对话的过短阈值 `dialog` + BGM 闪避音量 + 全部语音文案）、**`status`**
（`decayWhileAway` 决定"不在你面前"时要不要继续衰减）、**`pomodoro`**（预设档位/上下限/长休间隔/完成奖励）、
**`planner`**（条目上限与字数、装饰小桌宠的尺寸/透明度/角落）。
> 注意：`config.js` 里的值都是**默认值**，用户在窗口里改的偏好存 `settings.json`（`voice`/`pomodoro`/`planner`/
> `chatEngine` 字段），且会经过各自的清洗函数（白名单 + 夹取），手改 settings 不会把功能改坏。

- **P1.5**：待办到点气泡、催促使劲度、聊天命中/未命中、规则持久化；替换 blink/state 占位图生效；

- **P1.6 共存（遮挡根治回归）**：浏览器放 GIF/视频（含全屏）反复点击/拖动/抛丢桌宠 → 不动画冻结不黑屏；

  一段时间后仍点得动（遮挡禁用 + IPC 驱动判定双保险）。
- **P1.7 学英语**：学习▸学英语开窗；翻译判分三档、填空真题/生成题、背单词三连与复习打分；切难度/换主题/
  柔和标准切换重启记忆；词表搜索、☆生词本与「只背生词本」；统计页数字与近 7 天柱状；桌宠催背气泡按频率弹出。
- **P1.8 学习菜单三件套**：主菜单出现一级「学习」（学英语/番茄钟/学习计划表），学英语**不再**在聊天里；
  聊天里出现「语音聊天设置…」。番茄钟：预设与自定义时长真实计时、专注结束气泡+体力回复；
  计划表：加/勾/删、周视图切日、逾期与待安排分区、**右下角小桌宠与主图同源（换 pet.png 一起换）**。
- **P1.9 语音（需模型；缺模型时应表现为"优雅隐藏"）**：先跑 `npm run voice:e2e`（应打 `VOICE_E2E_OK`，
  它现在还会模拟"点 🎤 进入/退出语音对话"与"按一下全局键"）再动手试；`npm run voice:spike` 与 `voice:spike:electron` 都应输出"可用"；
  **重启应用后聊天窗应出现 🎤**（若没有、只显示一句"语音引擎还没准备好"，就是启动接线又断了 —— 直接跑 `npm run voice:e2e` 定位）；
  **点一下 🎤 → 状态条出现「语音对话中…」，直接说一句 → 说完静音约 1.2 秒自动断句、
  然后显示「在想…」（这期间麦克风应释放）→ 模型回复出现后自动继续听**（全程不需要再点任何东西）；
  故意"啊"一声 → **不应**发给模型，只提示"没听清";
  再点一次 🎤 → 退出对话、状态条消失；
  **按键说话（恢复后要重设一次键位）**：语音聊天设置 →「全局按键」框点一下 → 按 `Ctrl+3`（或你想要的键）→ 保存，
  提示应是"全局键 … 已生效"；然后**把聊天窗最小化/切到别的窗口**按一下那个键 → 桌宠应进入语音对话（状态条出现），
  再按一下 → 退出。聊天窗内按住 `Ctrl + Shift + Space` 说话、松开 → 应**立刻**提交（不用等 1.2 秒静音）；
  设一个已被占用的键保存 → 应明确提示"已被其它程序占用"；
  说唤醒词（默认「桌宠桌宠」）→ 也能叫醒一轮问答（**没进对话时桌面安静、什么都不显示**）；
  **识别期间 BGM 自动压低**；说话时拖宠物/弹菜单互不干扰；
  在语音聊天设置里点「重试」应能重建引擎（日志出现 `rebuild(user-retry)`）；
  **语音提示条与聊天气泡不许重叠**；唤醒误触发率与长时间监听 CPU 占用（这两项只能人工判断）。
- **P1.10 大模型（需自己填密钥；不想用就保持「回复引擎 = 关键词规则」）**：先跑 `npm run llm:e2e`
  （两阶段都应是 `LLM_E2E_OK`，它不需要真密钥）；然后聊天设置 → 大模型设置：选服务商 → 填密钥 → 保存 →
  「测试连接」应显示成功；**点「打开密钥文件位置」**应能定位到 `~\.deskpet\llm.key`（确认它**不在**桌宠文件夹里）；
  重启应用后密钥仍在（**去桌宠目录打开 `settings.json` 搜密钥，应搜不到明文；整个文件夹里也不该有密钥文件**）；
  把「回复引擎」切成大模型 → 聊天窗发一句，应收到模型回复；把密钥改错一位 → 应看到"已用本地规则兜底"的提示
  而不是没反应；把超时改成 3000ms 并在请求中按「停止」→ 应立即取消；勾「调试：强制回落」→ 应走规则兜底；
  勾「流式输出」→ 气泡应逐字出现；请求日志面板应能看到每次请求的耗时/状态码/tokens/路径。
- **P1.11 聊天记录**：聊几句 → 关掉聊天窗 → 再打开：**内容还在**（且开场白不会重复堆积）。

- **P2**：托盘全套；区域面板加减宽高实时生效、还原全工作区；隐藏即暂停（CPU 降）；
